## Welcome

Welcome to the Weya AI API documentation. These APIs let you manage everything you can do in the Weya AI dashboard from your own applications:

- **Agents** – voice, video and WhatsApp agents
- **Campaigns** – create campaigns, add contacts, start, pause, resume and update them
- **Phone Numbers** – connect and manage the numbers your agents call from
- **Knowledge Bases** – documents your agents answer from
- **Webhooks** – receive call outcomes in your own systems
- **DNC (Do Not Call)** and **Holiday Lists** – control who and when your campaigns call

## Base URL

All API requests should be made to:

```
https://api.weya.live/backend
```

## Authentication

Every endpoint is authenticated with an API key, sent in the `x-api-key` header:

```bash
x-api-key: YOUR_API_KEY
```

To create an API key, open the profile menu at the bottom of the dashboard sidebar and choose **API Keys**. Copy the key with the copy button next to it; the list itself only shows a masked version.

<Note>
An API key works only in the environment it was created in. A key created in a development dashboard is rejected by the production API with `401 Unauthorized: Invalid API Key`.
</Note>

<Warning>
Keep your API key secret. Anyone with it can act on your workspace. If a key is exposed, delete it from **API Keys** and create a new one.
</Warning>

## Phone Number Format

All phone numbers in API requests must include the country code. The `+` prefix is optional and will be automatically stripped if provided.

**Required Format:** `[country_code][area_code][number]`

**Examples:**
- ✅ **US:** `12125551234` (country code: 1, area code: 212)
- ✅ **UK:** `442071234567` (country code: 44)
- ✅ **Also works:** `+12125551234` (+ is automatically stripped)
- ❌ **Incorrect:** `2125551234` (missing country code)

<Note>
The country code is required for all phone numbers. You may include or omit the `+` prefix - both formats are accepted.
</Note>

## Campaign IDs

Campaigns were previously called *batches*. The API still uses the original names in paths and fields, so a campaign's ID is sent as `batchId` and its name as `batchName`, and campaign endpoints live under `/api/call/...` (for example `/api/call/delete-batch/{batchId}`).

## Response Format

All API responses follow a consistent format:

```json
{
  "message": "Success message",
  "status": true,
  "code": 200,
  "errorMessage": "",
  "data": { ... }
}
```

- `message` - Human-readable message describing the result
- `status` - Boolean indicating success (`true`) or failure (`false`)
- `code` - HTTP status code
- `errorMessage` - Error message (empty string on success)
- `data` - Response payload (varies by endpoint)

## Error Handling

API errors are returned with appropriate HTTP status codes:

- **400 Bad Request** - Invalid request parameters or missing required fields, including CSV files with invalid rows
- **401 Unauthorized** - Missing or invalid API key
- **403 Forbidden** - Insufficient permissions
- **404 Not Found** - Resource not found
- **409 Conflict** - The request conflicts with existing data, for example a phone number already active on another inbound campaign
- **500 Internal Server Error** - Server error; retry or contact support

## Rate Limiting

API requests are subject to rate limiting to ensure fair usage. If you exceed the rate limit, you'll receive a `429 Too Many Requests` response. Please implement exponential backoff when retrying requests.
