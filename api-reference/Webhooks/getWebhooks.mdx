title: "Get Webhooks"

---

## Overview

List the webhooks in your organization, including those created by other users in it. A webhook is a URL that call outcomes are sent to: add it to a campaign under **Track Call Outcomes** (`pushingCrms` with `type: "webhook"`), and the result of each finished call is sent to it as a JSON `POST` request. See [Create Webhook](/api-reference/Webhooks/createWebhooks) for how delivery works.

## Prerequisites

- An API key for your workspace

## Request

<ParamField header="x-api-key" type="string" required>
Your workspace API key. Create one from the profile menu in the dashboard → **API Keys**.
</ParamField>

<RequestExample>

```bash cURL
curl --location 'https://api.weya.live/backend/api/webhooks' \
  --header 'x-api-key: YOUR_API_KEY'
```

</RequestExample>

<ResponseField name="data" type="array[object]" required>
The webhooks in your organization. The list isn't paginated.
</ResponseField>

<ResponseField name="data[]._id" type="string">
Webhook ID. Use it as `crmId` and `schemaId` in a campaign's `pushingCrms`.
</ResponseField>

<ResponseField name="data[].name" type="string">
Name of the webhook.
</ResponseField>

<ResponseField name="data[].url" type="string">
URL that call outcomes are sent to.
</ResponseField>

<ResponseField name="data[].bearerToken" type="string">
Token sent as `Authorization: Bearer <token>` with each request. Empty if none was set. Returned in plain text, so don't log the response.
</ResponseField>

<ResponseField name="data[].isActive" type="boolean">
Stored flag. It doesn't stop deliveries; see [Update Webhook](/api-reference/Webhooks/updateWebhooks).
</ResponseField>

## Error Handling

- **401 Unauthorized** – Missing or invalid API key.
- **500 Internal Server Error** – Unexpected server error.
