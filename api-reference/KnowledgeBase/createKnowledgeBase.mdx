---
title: "Create Knowledge Base"
description: "Create a knowledge base from uploaded documents, or add documents to an existing one."
api: "POST /api/knowledgeBase/createKnowledgeBase"
---

## Overview

Upload documents that your agents can answer questions from. The files are stored and indexed for search before the response is returned.

If your organization already has a knowledge base with the same `knowledgeBaseName`, the files are added to it and the whole knowledge base is indexed again, instead of creating a second one. This is also the way to add files so that agents can use them; files added with [Update Knowledge Base](/api-reference/KnowledgeBase/updateKnowledgeBase) are not indexed.

To use a knowledge base, add its ID to an agent's `knowledgeBase` with [Create Agent](/api-reference/Agents/createAgent) or [Update Agent](/api-reference/Agents/updateAgent).

## Prerequisites

- An API key for your workspace
- One or more documents, sent as `multipart/form-data`

## Request

<ParamField header="x-api-key" type="string" required>
  Your workspace API key. Create one from the profile menu in the dashboard → **API Keys**.
</ParamField>

<ParamField body="knowledgeBaseName" type="string" required>
  Name of the knowledge base. Reusing an existing name adds the files to that knowledge base.
</ParamField>

<ParamField body="description" type="string">
  Description of the knowledge base.
</ParamField>

<ParamField body="files" type="file[]" required>
  Documents to upload: up to 50 files of up to 10 MB each. Send each file as its own `files` (or `files[]`) field. A file with the same name as an existing one replaces it.
</ParamField>

<RequestExample>

```bash cURL
curl --location 'https://api.weya.live/backend/api/knowledgeBase/createKnowledgeBase' \
  --header 'x-api-key: YOUR_API_KEY' \
  --form 'knowledgeBaseName="Customer Support KB"' \
  --form 'description="Knowledge base for customer support queries"' \
  --form 'files=@"/path/to/FAQ.pdf"' \
  --form 'files=@"/path/to/Pricing.pdf"'
```

</RequestExample>

    "description": "Knowledge base for customer support queries",
    "bucketUrl": "https://…/",
    "vectorDbCollection": "kb_customer_support_1a2b3c",

    "updatedAt": "2026-07-20T10:35:05.000Z"

</ResponseExample>

<ResponseField name="data._id" type="string">
  Knowledge base ID. Use it in an agent's `knowledgeBase`.
</ResponseField>

<ResponseField name="data.knowledgeBaseName" type="string">
  Name of the knowledge base.
</ResponseField>

<ResponseField name="data.vectorDbCollection" type="string">
  Name of the search index built from the files. A video agent uses it as `rag.vectorDBCollection`.
</ResponseField>

<ResponseField name="data.status" type="string">
  Always `PENDING`; it isn't updated. A successful response with a `vectorDbCollection` means the files were indexed.
</ResponseField>

## Error Handling

Errors return `status: false`, with the reason in `errorMessage`.

- **400 Bad Request** – `knowledgeBaseName is required`, `No files uploaded`, or a file over 10 MB or more than 50 files.
- **401 Unauthorized** – Missing or invalid API key.
- **429 Too Many Requests** – Rate limit reached. Wait and try again.
- **500 Internal Server Error** – Unexpected server error, or indexing failed (`Invalid response from external API`). The files may already be stored; send the request again with the same name.

<Check>
  After creating a knowledge base, you can:

  - `GET /api/knowledgeBase` – list your knowledge bases.
  - `GET /api/knowledgeBase/{knowledgeBaseId}/documents` – list its files.
  - Add it to an agent with `PATCH /api/agents/{id}` and `knowledgeBase: ["<knowledge base _id>"]`.
</Check>
