## Overview

Update an existing campaign to change its name, calling numbers, calling schedule, retry settings, DNC setting, holiday list or call outcome tracking. You can also add more calls to the campaign in the same request by attaching a CSV file.

The request can be sent in two ways:

- **JSON** (`application/json`) – to update settings only.
- **Form data** (`multipart/form-data`) – to update settings **and** add calls from a CSV file in one request.

## Prerequisites

- An API key for your workspace
- An existing campaign and its `batchId`. The campaign must have been created by the user who owns the API key.
- The campaign must be **paused** or **completed**. Pause a running campaign before updating it.
- Voice campaigns only. Chat campaigns can't be edited with this endpoint.

## Endpoint

<ParamField path="/api/call/update-batch/{batchId}" method="PUT">
</ParamField>

## Request

<ParamField header="x-api-key" type="string" required>
Your workspace API key. Create one from the profile menu in the dashboard → **API Keys**.
</ParamField>

<ParamField path="batchId" type="string" required>
Unique identifier of the campaign to update.
</ParamField>

<RequestExample>

```bash cURL (settings only)
curl --location --request PUT 'https://api.weya.live/backend/api/call/update-batch/6806382f98da85ec32fac955' \
  --header 'x-api-key: YOUR_API_KEY' \
  --header 'Content-Type: application/json' \
  --data '{
    "batchName": "Sales Campaign - July",
    "callingNumbers": ["6889c4ab7c7d3f9876543210"],
    "timezone": "Asia/Kolkata",
    "callingHour": { "start": "09:00", "end": "17:00" },
    "allowedDays": ["Monday", "Tuesday", "Wednesday", "Thursday", "Friday"],
    "retry": 3,
    "delay": 30
}'
```

```bash cURL (settings + CSV)
curl --location --request PUT 'https://api.weya.live/backend/api/call/update-batch/6806382f98da85ec32fac955' \
  --header 'x-api-key: YOUR_API_KEY' \
  --form 'batchName="Sales Campaign - July"' \
  --form 'callingNumbers="[\"6889c4ab7c7d3f9876543210\"]"' \
  --form 'retry="3"' \
  --form 'delay="30"' \
  --form 'file=@"/path/to/new-leads.csv"' \
  --form 'mandatoryVariables="[\"customer_name\"]"' \
  --form 'type="false"'
```

</RequestExample>

### Request Parameters

All settings are optional. Send only the fields you want to change; fields you leave out keep their current values.

<ParamField body="batchName" type="string">
Name of the campaign.
</ParamField>

<ParamField body="callingNumbers" type="array[string]">
IDs of the phone numbers used to place calls. Replaces the campaign's current list, so send every number the campaign should use. Calls are handled by the agent assigned to each number. Get the IDs from [Get Phone Numbers](/api-reference/PhoneNumbers/getPhoneNumbers).
</ParamField>

<ParamField body="timezone" type="string">
Timezone used for the calling schedule. Example: `Asia/Kolkata`.
</ParamField>

<ParamField body="callingHour" type="object">
Daily calling window in 24-hour `HH:MM` format. Both `start` and `end` are required. Example: `{ "start": "09:00", "end": "17:00" }`.
</ParamField>

<ParamField body="allowedDays" type="array[string]">
Days of the week calls can be placed on. Example: `["Monday", "Tuesday", "Wednesday", "Thursday", "Friday"]`.
</ParamField>

<ParamField body="retry" type="integer">
Maximum attempts per contact. Use a value from 1 to 10, the range the dashboard allows. The API does not check the range.
</ParamField>

<ParamField body="delay" type="integer">
Delay in **minutes** between attempts to the same contact. Use a value from 5 to 1440, the range the dashboard allows. The API does not check the range.
</ParamField>

<ParamField body="enableDNC" type="boolean">
  `true` to skip numbers on your Do Not Call list. Can be `true` only when DNC is enabled for your organization. `false` turns DNC checks off for this campaign.
</ParamField>

<ParamField body="holidayListId" type="string">
ID of the holiday list to apply. Send an empty string to remove the holiday list.
</ParamField>

<ParamField body="pushingCrms" type="array[object]">
Destinations call outcomes are sent to after each call. Replaces the current list. Send an empty array to stop tracking. A webhook or Google Sheet added here receives only calls that end after the update; earlier calls are not sent. Each item has:

- `type` – one of `standard` (HubSpot/Zoho), `custom`, `webhook` or `gsheet`
- `schemaId` – ID of the form or schema
- `crmId` – ID of the connection, webhook or Google Sheet integration
</ParamField>

### CSV Upload Parameters

Send these as `multipart/form-data` to add calls to the campaign. When using form data, send object and array fields (`callingNumbers`, `callingHour`, `allowedDays`, `pushingCrms`) as JSON strings, and `enableDNC` as `"true"` or `"false"`.

The settings are saved first, then the file is processed. If the file is rejected, the settings change is still saved.

The file uses the same columns as [Upload Campaign CSV](/api-reference/Campaigns/uploadCSV). New calls use the campaign's settings after this update.

<ParamField body="file" type="file">
File of contacts to add: `.csv`, `.xls` or `.xlsx`. Existing calls in the campaign are not removed. Not supported for inbound campaigns.
</ParamField>

<ParamField body="mandatoryVariables" type="string">
JSON array of variables that every row must have a value for. Example: `["customer_name"]`.
</ParamField>

<ParamField body="type" type="string">
`"true"` to skip invalid rows and upload only the valid ones. `"false"` (default) to reject the upload if any row is invalid. A file with no valid rows is always rejected.
</ParamField>

## Error Handling

Errors return `status: false`, with the reason in `errorMessage`.

- **400 Bad Request**
  - `Invalid Batch ID` – `batchId` is not a valid ID.
  - `Batch is currently running. Please pause this batch before updating.`
  - `A chat campaign cannot be edited here…` – the campaign is a chat campaign.
  - `callingHour` is missing `start` or `end`, or they are not in `HH:MM` format.
  - `Invalid JSON format for …` – a form field that must be a JSON string could not be parsed.
  - `enable DNC must be false in organization settings` – `enableDNC: true` was sent but DNC is not enabled for your organization.
  - A `pushingCrms` entry is invalid, for example its connection or schema does not exist.
  - `CSV upload is not allowed for inbound batches.`
  - The file is empty, is not CSV or Excel, or has no valid rows.
  - The file has invalid rows and `type` is `"false"`. `data` contains:

    - `code` – `INVALID_CSV_ROWS`
    - `totalInvalidRows` – number of invalid rows
    - `validRows` – rows that would be uploaded if invalid rows are skipped
    - `truncated` – `true` if `invalidRows` lists only some of the rows
    - `invalidRows` – list of `{ rowNumber, phoneNumber, reason }`

    Fix the rows, or resend with `type` set to `"true"` to skip them.
- **401 Unauthorized** – Missing or invalid API key.
  - `Unauthorized: Invalid API Key` – the `x-api-key` value is wrong, the key was deleted, or it was created in a different environment (for example the dev dashboard).
  - `Unauthorized: No API Key OR Token Provided` – the `x-api-key` header was not sent.
- **404 Not Found** – No campaign with this ID was created by the user who owns the API key, or it was deleted.
- **500 Internal Server Error** – Unexpected server error.

<Note>

A campaign that was **paused** resumes automatically after a successful update. You do not need to call the resume endpoint unless `data.queue_status` is still `paused`.

</Note>

<Note>

The scheduled start date is set when the campaign is created and cannot be changed with this endpoint.

</Note>

<Check>

After updating a campaign, you can:

- `GET /api/call/batch-details/{batchId}` to retrieve the updated campaign details.
- `POST /api/call/addCallsToBatch` to add more calls without changing settings.
- `POST /api/call/start-calling` to start calling.
- `DELETE /api/call/delete-batch/{batchId}` to delete the campaign.

</Check>
