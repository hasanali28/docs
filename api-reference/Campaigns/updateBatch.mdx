## Overview

Update an existing campaign to change its name, calling numbers, calling schedule, retry settings, holiday list or call outcome tracking. You can also add more calls to the campaign in the same request by attaching a CSV file.

The request can be sent in two ways:

- **JSON** (`application/json`) – to update settings only.
- **Form data** (`multipart/form-data`) – to update settings **and** add calls from a CSV file in one request.

## Prerequisites

- An API key for your workspace
- An existing campaign and its `batchId`
- The campaign must be **paused** or **completed**. Pause a running campaign before updating it.
- Calling numbers you pass must belong to the same workspace

## Endpoint

<ParamField method="PUT" path="/api/call/update-batch/{batchId}" />

## Request

<ParamField header="x-api-key" type="string" required>
Your workspace API key. Create one from the profile menu in the dashboard → **API Keys**.
</ParamField>

<ParamField path="batchId" type="string" required>
Unique identifier of the campaign to update.
</ParamField>

<RequestExample>

```bash cURL (settings only)
curl --location --request PUT 'https://api.weya.live/backend/api/call/update-batch/6806382f98da85ec32fac955' \
  --header 'x-api-key: YOUR_API_KEY' \
  --header 'Content-Type: application/json' \
  --data '{
    "batchName": "Sales Campaign - July",
    "callingNumbers": ["6889c4ab7c7d3f9876543210"],
    "timezone": "Asia/Kolkata",
    "callingHour": { "start": "09:00", "end": "17:00" },
    "allowedDays": ["Monday", "Tuesday", "Wednesday", "Thursday", "Friday"],
    "retry": 3,
    "delay": 30
}'
```

```bash cURL (settings + CSV)
curl --location --request PUT 'https://api.weya.live/backend/api/call/update-batch/6806382f98da85ec32fac955' \
  --header 'x-api-key: YOUR_API_KEY' \
  --form 'batchName="Sales Campaign - July"' \
  --form 'callingNumbers="[\"6889c4ab7c7d3f9876543210\"]"' \
  --form 'retry="3"' \
  --form 'delay="30"' \
  --form 'file=@"/path/to/new-leads.csv"' \
  --form 'countryCode="+91"' \
  --form 'mandatoryVariables="[\"customer_name\"]"' \
  --form 'type="false"'
```

</RequestExample>

### Request Parameters

All settings are optional. Send only the fields you want to change.

<ParamField body="batchName" type="string">
Name of the campaign.
</ParamField>

<ParamField body="callingNumbers" type="array[string]">
IDs of the phone numbers used to place calls. At least one is required if the field is sent. Calls are handled by the agent assigned to each number.
</ParamField>

<ParamField body="timezone" type="string">
Timezone used for the calling schedule. Example: `Asia/Kolkata`.
</ParamField>

<ParamField body="callingHour" type="object">
Daily calling window in 24-hour `HH:MM` format. Example: `{ "start": "09:00", "end": "17:00" }`.
</ParamField>

<ParamField body="allowedDays" type="array[string]">
Days of the week calls can be placed on. Example: `["Monday", "Tuesday", "Wednesday", "Thursday", "Friday"]`.
</ParamField>

<ParamField body="retry" type="integer">
Maximum attempts per contact. Allowed range: 1–10.
</ParamField>

<ParamField body="delay" type="integer">
Delay in **minutes** between attempts to the same contact. Allowed range: 5–1440.
</ParamField>

<ParamField body="holidayListId" type="string">
ID of the holiday list to apply. Send an empty string to remove the holiday list.
</ParamField>

<ParamField body="pushingCrms" type="array[object]">
Destinations call outcomes are sent to after each call. Send an empty array to stop tracking. Each item has:

- `type` – one of `standard` (HubSpot/Zoho), `custom`, `webhook` or `gsheet`
- `schemaId` – ID of the form or schema
- `crmId` – ID of the connection, webhook or Google Sheet integration
</ParamField>

<ParamField body="confirmReassign" type="boolean">
Inbound campaigns only. Set to `true` to move calling numbers that are already active on another inbound campaign to this campaign. See the `409` error below.
</ParamField>

### CSV Upload Parameters

Send these as `multipart/form-data` to add calls to the campaign. When using form data, send object and array fields (`callingNumbers`, `callingHour`, `allowedDays`, `pushingCrms`) as JSON strings.

<ParamField body="file" type="file">
CSV file of contacts to add. `.csv` only, up to 50 MB. Existing calls in the campaign are not removed. Not supported for inbound campaigns.
</ParamField>

<ParamField body="countryCode" type="string">
Country code used to validate phone numbers in the CSV. Example: `+91`.
</ParamField>

<ParamField body="mandatoryVariables" type="string">
JSON array of variables that every row must have a value for. Example: `["customer_name"]`.
</ParamField>

<ParamField body="type" type="string">
`"true"` to skip invalid rows and upload only the valid ones. `"false"` (default) to reject the upload if any row is invalid.
</ParamField>

## Error Handling

- **400 Bad Request** – Invalid field values, the campaign is still running (pause it first), or the CSV has invalid rows. For invalid rows, `data` contains:
  - `code` – `INVALID_CSV_ROWS`
  - `totalInvalidRows` – number of invalid rows
  - `validRows` – rows that would be uploaded if invalid rows are skipped
  - `truncated` – `true` if `invalidRows` lists only some of the rows
  - `invalidRows` – list of `{ rowNumber, phoneNumber, reason }`

  Fix the rows, or resend with `type` set to `"true"` to skip them.
- **401 Unauthorized** – Missing or invalid API key.
  - `Unauthorized: Invalid API Key` – the `x-api-key` value is wrong, the key was deleted, or it was created in a different environment (for example the dev dashboard).
  - `Unauthorized: No API Key OR Token Provided` – the `x-api-key` header was not sent.
- **404 Not Found** – The campaign does not exist in your workspace.
- **409 Conflict** – Inbound campaigns only. One or more calling numbers are already active on another inbound campaign. `data.requiresConfirmation` is `true` and `data.conflicts` lists each number as `{ phoneId, phoneNumber, currentBatchId, currentBatchName }`. Resend with `confirmReassign: true` to move them to this campaign.
- **500 Internal Server Error** – Unexpected server error.

<Note>

A campaign that was **paused** resumes automatically after a successful update. You do not need to call the resume endpoint.

</Note>

<Note>

The campaign type (outbound, inbound or mixed), DNC setting and scheduled start date are set when the campaign is created and cannot be changed with this endpoint.

</Note>

<Check>

After updating a campaign, you can:

- `GET /api/call/batch-details/{batchId}` to retrieve the updated campaign details.
- `POST /api/call/addCallsToBatch` to add more calls without changing settings.
- `POST /api/call/start-calling` to start calling.
- `DELETE /api/call/delete-batch/{batchId}` to delete the campaign.

</Check>
