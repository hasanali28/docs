title: "Resume Campaign"

---

## Overview

Resume a paused campaign so it starts placing calls again. If the current time is outside the campaign's calling hours or calling days, it waits until the next calling window.

You don't need to call this after **Update Campaign**: a paused campaign resumes automatically when its settings are updated.

## Prerequisites

- An API key for your workspace
- The campaign's `batchId`. The campaign must have been created by the user who owns the API key.
- The campaign is paused

## Endpoint

<ParamField path="/api/call/resume-batch/{batchId}" method="POST">
</ParamField>

## Request

<ParamField header="x-api-key" type="string" required>
Your workspace API key. Create one from the profile menu in the dashboard → **API Keys**.
</ParamField>

<ParamField path="batchId" type="string" required>
Unique identifier of the campaign to resume.
</ParamField>

This endpoint takes no request body.

<RequestExample>

```bash cURL
curl --location --request POST 'https://api.weya.live/backend/api/call/resume-batch/6806382f98da85ec32fac955' \
  --header 'x-api-key: YOUR_API_KEY'
```

</RequestExample>

## Response

<ResponseExample>

```json 200 OK
{
  "status": true,
  "code": 200,
  "message": "Batch resumed successfully",
  "errorMessage": null,
  "data": {
    "batchId": "6806382f98da85ec32fac955",
    "batchName": "Sales Campaign - July",
    "status": "pending"
  }
}
```

</ResponseExample>

<ResponseField name="status" type="boolean" required>
Indicates whether the campaign was resumed.
</ResponseField>

<ResponseField name="code" type="integer" required>
HTTP status code.
</ResponseField>

<ResponseField name="message" type="string" required>
Human-readable success message.
</ResponseField>

<ResponseField name="data.batchId" type="string">
ID of the resumed campaign.
</ResponseField>

<ResponseField name="data.batchName" type="string">
Name of the resumed campaign.
</ResponseField>

<ResponseField name="data.status" type="string">
New campaign status:

- `in-progress` – calls are waiting and the campaign is calling again.
- `pending` – the campaign will start calling.
- `freezed` – the current time is outside the campaign's calling hours, calling days or holiday list. Calling starts at the next calling window.
</ResponseField>

## Error Handling

Errors return `status: false`, with the reason in `errorMessage`.

- **400 Bad Request**
  - `Invalid Batch ID` – `batchId` is not a valid ID.
  - `Batch is not paused (current status: …)` – only a paused campaign can be resumed.
- **401 Unauthorized** – Missing or invalid API key.
- **404 Not Found** – No campaign with this ID was created by the user who owns the API key, or it was deleted.
- **500 Internal Server Error** – Unexpected server error.

<Check>

After resuming a campaign, you can:

- `GET /api/call/batch-details/{batchId}` to follow its calls.
- `POST /api/call/pause-batch/{batchId}` to pause it again.

</Check>
