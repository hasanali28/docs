## Overview

Queue a campaign's contacts for calling. Use it after [Upload Campaign CSV](/api-reference/Campaigns/uploadCSV), which creates the campaign and its contacts but doesn't start calling.

Every contact in the campaign that hasn't been called to a `completed` or `failed` result is queued. Call it once per upload. Calls are placed during the campaign's calling hours and allowed days. The request returns once the contacts are queued; follow progress with [Get Campaign Details](/api-reference/Campaigns/getBatchById).

Contacts added with [Add Calls to Campaign](/api-reference/Campaigns/addCallsToBatch) are queued automatically, so you don't need this endpoint for them.

## Prerequisites
- An API key for your workspace
- A campaign with contacts, and the `uuid` from its Upload Campaign CSV response

## Request
<ParamField header="x-api-key" type="string" required>
Your workspace API key. Create one from the profile menu in the dashboard → **API Keys**.
</ParamField>

<ParamField body="batchId" type="string" required>
ID of the campaign to start.
</ParamField>

<ParamField body="callingNumbers" type="array[string]" required>
IDs of the phone numbers to call from. At least one valid ID. Usually the campaign's own calling numbers.
</ParamField>

<ParamField body="uuid" type="string" required>
Upload ID returned by Upload Campaign CSV (`data.uuid`). The request fails without it.
</ParamField>

<ParamField body="scheduleAt" type="string">
Date and time (ISO 8601) to start calling instead of now. Example: `2026-12-01T09:00:00.000Z`.
</ParamField>

<ParamField body="userId" type="string">
Not needed with an API key: the user who owns the API key is used.
</ParamField>

<RequestExample>
```bash cURL
curl --location 'https://api.weya.live/backend/api/call/start-calling' \
  --header 'x-api-key: YOUR_API_KEY' \
  --header 'Content-Type: application/json' \
  --data '{
    "batchId": "6806382f98da85ec32fac955",
    "callingNumbers": ["64e5f12345abcdef87654321"],
    "uuid": "3f6c2a1e-8b4d-4f7a-9c1e-2d5b7a9e0f11"
  }'
```
</RequestExample>

## Response

<ResponseExample>
```json 200 OK
{
  "status": true,
  "code": 200,
  "message": "Calling service started successfully",
  "errorMessage": null,
  "data": {
    "success": true,
    "message": "Calls queued successfully",
    "totalCalls": 100,
    "batchId": "6806382f98da85ec32fac955",
    "batchName": "Marketing Campaign May 2025"
  }
}
```
</ResponseExample>

<ResponseField name="data.totalCalls" type="integer">
Number of contacts queued.
</ResponseField>

<ResponseField name="data.batchId" type="string">
Campaign ID.
</ResponseField>

<ResponseField name="data.batchName" type="string">
Campaign name.
</ResponseField>

## Error Handling

Errors return `status: false`, with the reason in `errorMessage`.

- **400 Bad Request**
  - `Invalid Batch ID`.
  - `No valid phone IDs provided` – `callingNumbers` has no valid ID.
  - `No valid calls to process` – the campaign has no contacts left to call.
- **401 Unauthorized** – Missing or invalid API key.
- **404 Not Found** – `Batch not found`.
- **500 Internal Server Error** – Unexpected server error, including a missing `callingNumbers` or `uuid`, or more than 50,000 contacts to queue.

<Note>
To pause or resume a running campaign, use [Pause Campaign](/api-reference/Campaigns/pauseBatch) and [Resume Campaign](/api-reference/Campaigns/resumeBatch).
</Note>
