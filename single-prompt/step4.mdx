Post-call metrics are the structured results weya extracts from every conversation after it ends, such as whether the issue was resolved, a promised payment date or a satisfaction score. They appear in the dashboard for each call and in the `call_analysis` field of your [call result webhook](/integration/webhooks), one entry per metric with its `metric_name` and `metric_value`.

## Add a metric

For each metric, set three fields.

### Metric name

A unique, descriptive name, for example `Customer Satisfaction`, `Order Status` or `Follow-up Required`. It is sent as `metric_name`, so pick a name your systems can map.

### Data type

| Type | Use it for |
| --- | --- |
| **Text** | Free-form summaries or notes |
| **Single Extract** | One specific value, such as the customer's answer to a question |
| **Boolean** | Yes or no outcomes: was the order placed, was the issue resolved |
| **Timestamp** | The exact time something happened in the call |
| **Date** | Calendar dates, such as an appointment date |
| **Numeric** | Quantities, ratings or scores |
| **Multi Extract** | Several values from the same call |

### Description

Tell the AI exactly what to extract and in what format. This is the instruction it follows, so be specific.

```text Example
Metric name: Customer Satisfaction Score
Data type: Numeric
Description: Extract a rating from 0 to 10 based on how satisfied the customer sounds.
If the customer gives a rating directly, use that value. Otherwise, estimate it from
the conversation.
```

## Tips

- Give each metric a name your team and your integrations will recognise.  
- Choose the narrowest data type that fits, so values are easy to filter and report on.  
- State the format you want for dates and numbers in the description.

<Warning>
  A completed call is sent to your webhook only once its analysis is ready. If analysis isn't ready within 30 minutes of the call, the result is not sent. See [When results are sent](/integration/webhooks#when-results-are-sent).
</Warning>
